# make-explainer-animated-videos

The user records a **voice-over** (English, or Roman-script Hinglish) and has a **script**. This skill cleans the voice, designs the visuals (a storyboard in `scenes.json`), builds a HyperFrames project, masters the audio, checks everything, renders a draft, and after approval produces the final MP4, covers, subtitles and posting kit. Read `references/STYLE_ANALYSIS.md` (what the look is and why) before storyboarding.

**If `PERSONAL.md` exists in this folder, read it first: it holds the owner's handle, approval rules, paths and channel rules, and overrides the defaults below.** Per-user settings live in `config.local.json` (see `docs/USAGE.md`).

`K` = this folder (e.g. `~/.claude/skills/make-explainer-animated-videos/`) · projects live in the `projects_dir` from config (default `~/Documents/explainer-videos/<slug>/`) · `examples/sample/` is a working storyboard.

## Hard rules
- **Free + open source only:** HyperFrames (Apache-2.0, HTML to MP4 in headless Chrome), Canvas 2D + CSS for backdrops and UI, three.js (MIT, vendored in `assets/vendor/`) for the 3D layer (WebGL runs on the GPU path of HyperFrames' headless Chrome; every frame is still a pure function of time), ffmpeg, whisper.cpp (MIT), fonts under SIL OFL, SFX synthesised by `scripts/make_sfx.py`. **GSAP** is used only as the paused timeline clock: free under GreenSock's own licence, not OSI open source (swap for Anime.js if that matters).
- **The user's voice is the audio, and it comes first.** Never generate a voice (a TTS voice is for smoke-testing the pipeline only). It is cleaned once, up front, by `clean_voice.py` (`references/VOICE_CLEANUP.md`); the original file is never touched; the music is solved around it, never the other way round.
- **Every video gets a music bed** from a library the user may legally use (`config.local.json` `music_dir`, built with `scripts/build_music_index.py`); the licence line is copied to `assets/music_credit.txt`. Default style `premium` = techno / tech-house / house / technology beds with a dark spectrum and a driving groove, never pop, funk, corporate or ambient (`python3 -I K/scripts/audio_lib.py --rank premium`; `alt_mix.py` A/Bs another track in seconds). Mix target: voice 10-14 dB over music + SFX (median), never closer than 8 dB, master -14 LUFS, true peak <= -1.5 dBTP.
- **Copy the format, not a brand.** The header shows the user's own handle (`meta.handle` or config). Never reuse another creator's name, characters, scripts or examples.
- **Never invent facts.** Every counter/bars carries `"src"` or is auto-labelled as a simplified example; do not assert company/product facts the research could not source.
- **Approvals:** ask whenever a sign-in is needed; show the draft + contact sheet before calling anything final; upload only after the user approves BOTH the video and the covers; never post anything for the user.

## Workflow
0. **Setup (once per machine):** `bash K/scripts/setup.sh` (Node 22+, ffmpeg, whisper-cli + `ggml-small.en` model, GSAP cache, fonts, numpy). Optional: `pip install librosa` for `build_music_index.py`. The first render downloads Chrome (1-2 min).
1. **Inputs.** Need the voice file (wav/mp3/m4a/aiff) and the script. Create `<projects_dir>/<slug>/` with `voice.<ext>` and `script.txt`. Ask for exactly what is missing. Check the voice with `ffprobe` (>= 44.1 kHz, no clipping); 8 kHz phone audio: ask for a re-record.
2. **Voice cleanup (automatic inside the build).** `clean_voice.py`: first word ~0.05 s in, sentence gaps capped at 0.22 s and phrase gaps at 0.12 s (cut from the middle, breaths go with it), standalone fillers (um/uh/ahh/hmm) deleted, drawn-out vowels shortened, repeated phrases keep the last take, +/-3 dB level matching across recorded parts, then a voice chain (high-pass, denoise, EQ, de-ess, compress). Writes `voice_clean.wav` + `assets/voice_edit.json` (every removed span with its reason): READ it at the checkpoint. A hand-timed `words_override.json` stays in the ORIGINAL voice's timeline and is re-mapped automatically. Off: `meta.voice_clean: false`.
2b. **Language.** English: nothing to set (whisper aligns the script). **Roman-script Hinglish** (or any language whisper cannot read): `"language": "hinglish"` in `meta` = island-anchored timing (acoustic speech islands + per-island whisper-medium with a Roman prompt as soft evidence, fuzzy-aligned to the script); a `words_override.json` always wins. Ask for ~0.3-0.5 s pauses between sentences when recording. Island starts are reliable; words inside a fast island are +/-0.2-0.4 s. The caption font has no Devanagari: keep scripts in Roman letters.
3. **Storyboard -> `scenes.json`** (schema + recipes: `references/STAGE_LIBRARY.md`; working example: `examples/sample/scenes.json`):
   - **One spoken sentence = one scene**, 8-18 words; split long sentences at commas so every half gets its own visual. `text` must be the sentence exactly as spoken; mark the 1-3 meaning words with `*key*`.
   - Hook scene (the question; in ink worlds `hero: null` and one explaining visual, in classic worlds a moving hero), a concrete everyday example, the mechanism one step per sentence, a failure/twist (red), the fix (green), a recap `list`, then the `cta` bubble.
   - One new visual idea per scene; persist the diagram across scenes (same `id`s, `keep`). Stage content in y 480-1450, cards <= 780 px wide, hero offset -250...-350 above a low diagram, nothing below y 1500.
   - Colour = meaning: one accent per concept (primary/active, second, third, green success, red failure). Land key visuals on spoken words with `"at": "<word>"`. `"shock": true` on the 3-4 reveal scenes.
   - Facts: `"src": "<where the number comes from>"` on counters/bars, or they are labelled "SIMPLIFIED EXAMPLE".
4. **Build:** `python3 -I K/scripts/build_explainer.py <proj>` -> `index.html` + `assets/` and it masters the audio (`assets/audio/master.wav`, `assets/mix_report.json`). It prints the world, voice cleanup, facts, transitions/punches, music, mix balance and "script/voice match": below 80% means the script differs from the recording. `python3 -I K/scripts/mix_audio.py <proj>` re-solves only the mix (seconds).
4b. **Layout gate (mandatory, before any render):** `python3 -I K/scripts/layout_check.py <proj>` must print PASS: no overlaps, nothing in the caption zone / outside the margins, balanced vertical rhythm. Fix the storyboard, never ignore it.
5. **Check:** `cd <proj> && npx --yes hyperframes@0.8.209 check` (0 errors; accepted: canvas-edge info, `line_unread` on fast speech, `text_below_floor` on mono texture labels). Fix every contrast/overlap finding.
6. **Look:** `npx --yes hyperframes@0.8.209 snapshot --at <scene midpoints>`; also `T-0.07, T, T+0.1` of every transition. Nothing covered, nothing overlapping, the incoming scene already shows content at the cut.
7. **Draft:** `npx --yes hyperframes@0.8.209 render -o renders/picture.mp4 -q delivery -f 30` (`-q draft` while iterating), then `bash K/scripts/finalize.sh renders/picture.mp4 renders/<slug>_final.mp4 assets/audio/master.wav`, then `python3 -I K/scripts/qa_explainer.py <proj> renders/<slug>_final.mp4` (resolution, loudness, mix balance, voice cleanup stats, SFX density, silent spots, visible change <= 3.2 s, budgets; contact sheets in `qa/`) and `python3 -I K/scripts/safe_zone_check.py <proj> renders/<slug>_final.mp4`. Max 3 fix rounds.
8. **Checkpoint (one message):** the video, `qa/` sheets, a one-line list per scene, the length, the voice-edit list, the facts register, anything not verified. Wait for approval.
9. **Publish pack** (all gated; details `references/PUBLISHING.md`): `meta.headline` (frame-0 claim: line 1 the belief, line 2 the twist) -> `make_cover.py` (covers A/B + 3:4 grid check) -> `make_srt.py` -> research (`seo_research.py` + web searches, save `research_notes.md`) -> write `posting_kit.md` from `assets/posting-kit-template.md` -> `kit_lint.py` PASS -> LinkedIn (`linkedin_post.md` + `make_linkedin_image.py`) -> `publish_check.py`.
10. **Upload:** `bash K/scripts/upload_drive.sh <proj> --dry-run` shows the plan; the real run needs `--approved-video --approved-cover` after the user approves BOTH, goes to a NEW `<drive_dest>/<reel>/` subfolder (`<reel>_vN` -> `<reel>/vN/`) and verifies sizes. Never otherwise.

## What makes it hook (built in; `references/ENERGY_AND_SOUND.md`)
Opening camera snap, slow drift, camera punches on number/negation/key words (every 3rd with shake), at most one transition per ~9 s at idea changes (whip / focus pull / vertical whip / push, each with its own sound), impact rings on `shock` reveals and stamps, riser -> hit before the first stamp, beat-locked glow and particle pulse, film grain, a gap filler so nothing sits still for > 3 s, music + SFX by role, no empty frames after a cut.

## Worlds (variety)
`assets/worlds.json`. **Default (calm premium, one accent): ink_blue, ink_violet, ink_teal, ink_amber** (auto-rotated so two videos in a row never share an accent). Expressive multicolour (only if the user asks for loud): neon_studio, fluted_chrome, sunset_duotone, editorial_studio. Classic mono (on request): mono_pulse, blueprint, amber_signal, terminal_green. **Read `references/DESIGN_PRINCIPLES.md` before storyboarding: restraint, one accent, a fixed grid, no decorative objects.** A world = palette, backdrop, glass/flat style, zone colours, caption style, motion strength, transition order, preferred music genres. Authoring rules for the polished look: `references/STAGE_LIBRARY.md` section "v0.7 studio elements"; why it looks like this: `references/STYLE_ANALYSIS.md` second batch. `meta.world` or auto-rotation that never repeats either of the last two videos (`<projects_dir>/_style_log.json`); a re-edit keeps its world and track. Add your own: `docs/TWEAKING.md`.

## Options (`scenes.json` -> `meta`)
`world` - `language` ("hinglish") - `handle` - `series` - `headline` - `cover` - `voice_clean` / `voice_chain` / `sentence_gap` / `phrase_gap` / `voice_reclean` - `music` (false) / `music_style` ("premium" | "classic") / `music_skip` / `music_bpm` / `music_file` - `objScale` (1.3) - `drift` - `hinglish_asr` (false = pause-based only) - `illustrative_label` - scene `shock`. Element and hero fields: `references/STAGE_LIBRARY.md`.

## How it works
`build_explainer.py` cleans the voice, aligns script words to time, resolves element lifetimes and keyframes, plans camera/transitions/SFX (`fx_plan.py`), picks music and SFX (`audio_lib.py`), masters the audio (`mix_audio.py`) and inlines everything into one `index.html`. `engine.js` makes **every pixel a pure function of time** (`render(t)`), driven by one paused GSAP tween: canvas = dust + ~4k-particle morphing hero + wireframes/links/packets; DOM = captions, chips, cards, counters. Deterministic and seekable; seeded RNG only. `docs/ARCHITECTURE.md` has the map.

## Known limits
3D objects are procedural primitives (no imported models/GLB yet); one particle hero at a time; no post-processing bloom (glow is faked with lights and CSS) (raise `meta.particles` to 6000 if the machine copes); the typefaces are the closest free matches to the studied look; no presenter/avatar; automatic filler detection only catches sustained sounds ("aaa", "ummm"); Hinglish word timing inside fast islands is approximate; the mix is judged by numbers, so listen once with headphones before the checkpoint. Render is about 2x real time for a draft, 3x for delivery.

## Study mode
`bash K/scripts/study_reference.sh <out_dir> <url...>` downloads public videos (yt-dlp) for style analysis (sheets, beat/motion/luma metrics, loudness). Analyse for craft; do not redistribute or copy someone's brand.
